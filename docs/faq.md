# 常見問題

## 支援哪些 Android 版本？哪些裝置已經測過？

最低需求是 Android 9（API 28），目前以 Android 16（API 36）為目標版本。最低版本可安裝，不代表每個品牌與系統組合都已驗證。

Android 9 模擬器已驗證安裝、開啟、座標定點與中斷後清理；獨立接收器確認 GPS、network 與 Google fused 收到持續更新的模擬定點。OPPO CPH1941（Android 11／API 30）已驗證行走、暫停、繼續、停止行走、恢復真實定位與背景設定入口，並由獨立接收器確認位置輸出及恢復後的非模擬樣本。Android 15／16 模擬器也曾驗證初版跨 App 輸出、路線與部分生命週期行為，但不能將初版結果當成所有新版功能的完整回歸。

Android 9 模擬器已驗證新版介面的選點、三種模式切換、速度調整、行走、暫停／繼續與停止；Route Probe 確認停止後三路定位仍更新、速度為零且位置不漂移。停止中的模擬行程按「定位」也已確認能釋放模擬並回到真實位置。

OPPO Android 11 已確認新版介面開啟後能取得真實位置並置中，原有目的地、速度與模式保留。原路往返與閉合循環的完整行走、新步行起點檢查的各種拒絕情境尚未完成裝置端驗證。其他品牌、數小時行走、拔除充電連線後的長時間熄屏，以及完整 Doze 情境尚未驗證。

## 第一次使用要設定什麼？

1. 開啟手機的系統定位，允許 Route Mock 使用位置；系統提供精確／概略選項時，請選擇精確位置。
2. 在系統「關於手機」連按版本號碼啟用開發人員選項，再於「選取模擬位置應用程式」選擇 Route Mock。名稱與入口依手機而異，App 的「設定」提供說明與捷徑。
3. 允許通知，以便使用通知中的行程操作。Android 13 起會另外要求通知權限。
4. 回到 Route Mock，等待取得真實位置，或按上方「定位」重試，再加入目的地、定點或規劃路線。

定位輸出由位置類型的前景服務負責，可在切換到其他 App 後繼續運作；前景服務與通知仍不能保證廠商不會限制背景程序。不需要 root，也不需要開啟開機自動啟動。

## 切換 App 或熄屏後位置停止更新，怎麼辦？

開啟 Route Mock「設定 → 背景執行設定」，進入本 App 的系統資訊頁，再找到電池或背景執行選項。

在已測試的 OPPO 手機上，需於「耗電管理」開啟「允許完全背景行為」。只變更這個 App 的設定後，切換到 Pikmin 前景與熄屏的短期觀察均保持位置更新；未開啟時，即使前景服務還在，ColorOS 仍曾凍結程序。

其他手機可能稱為「允許背景活動」或「不限制電池用量」，入口與效果依品牌、系統版本而異。這個按鈕只開啟 App 資訊頁，不會自動修改設定。已驗證的改善限該 OPPO 裝置與短期觀察，不能保證所有 OEM 或數小時不中斷。

## 主畫面的操作放在哪裡？

地圖右側依序提供「定位」、「輸入座標」、「撤回途經點」、「清除路線」四個圖示，長按可查看名稱。定位用來取得真實位置；右上角齒輪提供定位權限與背景執行說明。地圖以雙指縮放、拖曳移動，不另顯示放大／縮小按鈕。短螢幕會將四個工具改為兩欄，保留地圖與署名的空間。

下方依序是路線摘要與規劃、行走模式及速度；可上下捲動查看提示與目前路線位置。

「定點」與「開始行走」固定在底部。模擬行程啟動後，底部改為「暫停／繼續」、「停止行走」及獨立的「恢復真實定位」，不必捲動尋找。不能用於當前狀態的操作會停用，例如定點時不能暫停。橫向畫面會將地圖與設定並排顯示。

## 怎麼選點與規劃路線？會自己隨機走嗎？

步行路線的第一點 A 由手機的真實位置自動建立，地圖不再固定以台北為中心。取得起點後，可以點按地圖加入目的地，或用「座標」輸入「緯度, 經度」。緯度範圍為 −90 至 90，經度為 −180 至 180。尚無起點時，不能加入第一個目的地。

定點使用最後選取的途經點。步行規劃接受總共 2–8 個有順序的途經點，包含自動建立的起點與最多 7 個目的地；服務可能將它們對齊附近可步行路網。「清除」移除目的地但保留起點，「復原」也不會移除起點。先選擇行走模式、規劃並檢查預覽，再開始行走；規劃失敗會顯示錯誤，不會偷偷改用直線。

行走沿確認的軌跡依選定速度前進，不會隨機選方向。速度可設為 0.5–30 km/h，預設 5 km/h，行走中可以調整。這不是 Google Maps 路線，也不支援 Google Maps 分享連結或 GPX 匯入。

## 「定位」會做什麼？為什麼有時需要等待？

沒有活動中的模擬行程或待清理狀態時，開啟 App 會取得真實位置；可用時先採用 10 秒內的合格位置，避免反覆等待 GPS。地圖右側的定位圖示可主動定位；真實位置以藍色標記，模擬位置以橘色標記顯示。

在模擬行程中按「定位」，就表示要先結束模擬輸出並清理，再等待新的真實位置；可能因此跳回手機所在處。若只是切回正在執行的 App，會保留模擬行程，不會自行釋放。清理尚未完成時不會使用模擬樣本充當真實位置。

定位會使用 GPS、network，以及可用的 Google 融合定位。只接受非模擬樣本、合法座標與大於 0 且至多 50 公尺的精度；一般定位可使用 10 秒內的合格結果，過期或模擬樣本不會被採用。釋放模擬後，還會排除這次清理完成前的樣本。

每次取得位置最多等待 25 秒，離開畫面會取消請求；室內、系統定位關閉或權限不足時仍可能失敗。融合定位失敗不會中止 GPS／network 的等待，也不會放寬精度限制。

## 為什麼規劃或開始時又要求定位？

「規劃」可沿用這次開啟畫面後已取得、30 秒內且精度合格的真實位置；超時才重新定位。重新使用前仍會檢查精確位置權限、系統定位及模擬狀態。

「開始行走」仍要求按下開始之後的新樣本，避免規劃後人已移動，卻從舊位置出發。若手機已移動超過起點允許誤差，App 會更新 A、清除已規劃軌跡，保留其餘目的地、速度與模式，要求重新規劃。儲存過目的地不代表可以略過這項檢查。

起點允許誤差取 10 公尺與該次定位回報精度中的較大值。路由對齊路網後的起點若距離真實位置超出此範圍，App 不會直接開始，也不會自動改路並出發；請重新規劃與檢查預覽。

這項保護限步行路線，仍受定位精度與路網對齊影響，不保證絕對零跳點或遊戲接受。「定點」刻意使用最後選取的位置；選擇遠方位置定點仍可能跳到該處。

## 定點、暫停、停止行走與恢復真實定位有何差別？

| 操作或狀態 | 位置輸出與後續行為 |
| --- | --- |
| 定點 | 在選定位置持續輸出零速度與新的時間戳。 |
| 暫停 | 停在目前位置並保留進度，可按「繼續」從原進度行走。 |
| 停止行走 | 固定最後採樣位置，持續輸出零速度與新的時間戳；不能按「繼續」重啟這次移動。 |
| 單次到達終點 | 留在終點定點，不會自行返回起點。 |
| 恢復真實定位 | 結束模擬輸出並清理本 App 啟用的定位狀態；接收 App 可能跳回手機真實位置。 |

主畫面與通知提供停止行走及恢復真實定位。停止行走仍是活動中的模擬行程，編輯路線或開始另一段行程前，需先恢復真實定位。

## 單次、原路往返與閉合循環怎麼走？

開始前可在主畫面的三個選項中擇一。以真實起點 A 與依序加入的目的地 B、C 為例：

| 模式 | 行走方式 |
| --- | --- |
| 單次 | A → B → C，到達 C 後維持定點。 |
| 原路往返 | A → B → C → B → A，沿同一條已規劃軌跡反向走回，持續往返。 |
| 閉合循環 | A → B → C → A，將 C 回到 A 的步行路線一起規劃，持續循環。 |

閉合循環不會用直線補回程或瞬間跳到起點；路由結果的首尾座標必須完全相同，否則規劃會報錯。回程仍依步行路網，請在開始前檢查完整預覽。

「單次」與「原路往返」之間切換可沿用已規劃軌跡；切入或離開「閉合循環」都會清除軌跡，需要重新規劃。規劃中、模擬行程中與清理中不能切換模式；暫停或停止行走後仍在輸出定點，需先「恢復真實定位」才能修改。

模式只影響路線行走；「定點」仍固定在最後選取的途經點。沒有途經點停留時間或圈數計數功能。

## 「路線位置」是累積里程嗎？

不是。「路線位置」表示目前沿已規劃軌跡，距離軌跡起點多少公尺；後方數字是這條軌跡的總長度。

原路往返時，去程數字增加、回程減少；閉合循環每走完一圈會回到 0。這不代表位置瞬間跳動，也不是累積行走里程或遊戲步數。

## 能保證位置不跳回真實位置嗎？

單次到達、暫停與停止行走都維持模擬定點。

「停止行走」不會主動釋放模擬定位，但無法保證接收 App、系統或程序中斷時的顯示行為。明確按下「恢復真實定位」會釋放輸出，接收端可能跳回真實位置；此操作不承諾平滑走回或避免跳點。

## 一定要連網嗎？資料會保存嗎？

規劃新路線需要連網，尚未快取的地圖圖磚也需要連線。已下載並保存的路線軌跡，在取得新的真實位置並通過起點檢查後可以離線行走；若起點改變而需要重新規劃，仍需連網。沒有圖磚時仍可在取得起點後輸入座標定點。公共圖磚與路由服務沒有本專案專屬的可用性保證。

App 在手機本機保存最近一份草稿，包括途經點、已規劃軌跡、速度與行走模式。修改途經點會使原軌跡失效，需要重新規劃。舊版草稿會保留原有資料，模式預設為「單次」；使用保存的路線前仍需新的真實位置，起點改變時會保留其餘目的地並要求重新規劃。沒有多筆路線歷史；資料不參與雲端備份或裝置轉移。

重新開啟、程序重建或手機重開機都不會自動開始／續走。若原服務仍在執行，回到畫面可查看現有行程；若程序已中斷，保存的草稿不會恢復中斷時的進度。

## Pikmin Bloom 或 Pokémon GO 可以使用嗎？

在一台 OPPO Android 11 手機調整背景限制後，使用者已目視確認 Pikmin Bloom 152.0 的地圖位置持續前進。這只證明該裝置與遊戲版本的地圖移動，沒有驗證步數增加、完整遊玩、其他品牌或數小時穩定性。Pokémon GO 尚未實測。

獨立接收器收到位置，不等於遊戲接受或能正常遊玩。Route Mock 保留 Android 的模擬定位標記；接收 App 可以辨識並拒絕。本專案不提供 root 整合、隱藏模擬標記、修改遊戲或繞過偵測的功能。

## 座標會傳到哪裡？需要帳號或 API key 嗎？

不需要帳號或自行申請 API key。地圖使用 OpenStreetMap 圖磚，Leaflet 程式與樣式隨 App 打包。按下規劃時，真實起點與選取的目的地座標會送到 FOSSGIS 的 `routing.openstreetmap.de/routed-foot` 服務；該服務會記錄請求。圖磚請求也會送到圖磚供應方。

App 在前景讀取真實位置，用於地圖與步行起點檢查。單純開啟 App 或按「定位」不會把座標送到路由服務；只有要求規劃時才會傳送起點與目的地。地圖顯示仍會正常請求相關區域的圖磚。App 自有程式沒有分析追蹤或背景蒐集真實位置的功能。這不代表第三方 SDK 與系統服務已完成全面隱私稽核。供應方政策與授權請見[第三方聲明](../THIRD_PARTY_NOTICES.md)。

## 沒有 Google Play services 可以使用嗎？

Google Play services 正常時，App 同時提供 GPS、network 與 Google fused 模擬輸出。完全未安裝 Google Play services 時才使用平台定位模式；已安裝但停用、過舊或異常時會明確報錯。完整的 GMS 缺席與異常裝置矩陣尚未驗證。

## 恢復真實定位後仍顯示舊位置，或清理失敗怎麼辦？

接收 App 可能快取最後位置，恢復後需等待裝置取得新的真實定位；室內也可能暫時沒有新的 GPS 樣本。清理成功不代表接收端立即更新畫面。

強制停止或程序異常中斷可能留下待清理狀態。重新開啟 Route Mock，使用「清理並恢復真實定位」。若已將其他 App 指定為模擬位置 App，請先重新選回 Route Mock，再重試清理。

畫面若仍顯示清理中或錯誤，代表尚未確認釋放完成，不能當作已恢復真實定位。外部定位服務尚未完成的操作也可能延後清理；保留錯誤訊息以便排查，不要把「停止行走」當成清理操作。

## Release APK 可以直接覆蓋安裝嗎？

本專案的 Release 使用固定且公開的測試簽署金鑰，同一身分的較新版本可用於更新。既有 debug APK 通常使用不同簽章，需要先解除安裝；解除安裝會移除本機草稿。

任何人都能取得此公開金鑰並簽署 APK，因此相同憑證不能證明發布者身分。請從本儲存庫的 Releases 頁取得 APK；金鑰與更新限制見[簽署說明](../signing/README.md)，建置與發布指令見 [README](../README.md)。
