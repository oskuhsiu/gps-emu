# 常見問題

## 支援哪些 Android 版本？哪些裝置已經測過？

最低需求是 Android 9（API 28），目前以 Android 16（API 36）為目標版本。最低版本可安裝，不代表每個品牌與系統組合都已驗證。

Android 9 模擬器已驗證安裝、開啟、座標定點與中斷後清理；獨立接收器確認 GPS、network 與 Google fused 收到持續更新的模擬定點。OPPO CPH1941（Android 11／API 30）已驗證行走、暫停、繼續、停止行走、恢復真實定位與背景設定入口，並由獨立接收器確認位置輸出及恢復後的非模擬樣本。Android 15／16 模擬器也曾驗證初版跨 App 輸出、路線與部分生命週期行為，但不能將初版結果當成所有新版功能的完整回歸。

其他品牌、數小時行走、拔除充電連線後的長時間熄屏，以及完整 Doze 情境尚未驗證。

## 第一次使用要設定什麼？

1. 開啟手機的系統定位，允許 Route Mock 使用位置；系統提供精確／概略選項時，請選擇精確位置。
2. 在系統「關於手機」連按版本號碼啟用開發人員選項，再於「選取模擬位置應用程式」選擇 Route Mock。名稱與入口依手機而異，App 的「設定」提供說明與捷徑。
3. 允許通知，以便使用通知中的行程操作。Android 13 起會另外要求通知權限。
4. 回到 Route Mock，選點、定點或規劃路線後開始。

定位輸出由位置類型的前景服務負責，可在切換到其他 App 後繼續運作；前景服務與通知仍不能保證廠商不會限制背景程序。不需要 root，也不需要開啟開機自動啟動。

## 切換 App 或熄屏後位置停止更新，怎麼辦？

開啟 Route Mock「設定 → 背景執行設定」，進入本 App 的系統資訊頁，再找到電池或背景執行選項。

在已測試的 OPPO 手機上，需於「耗電管理」開啟「允許完全背景行為」。只變更這個 App 的設定後，切換到 Pikmin 前景與熄屏的短期觀察均保持位置更新；未開啟時，即使前景服務還在，ColorOS 仍曾凍結程序。

其他手機可能稱為「允許背景活動」或「不限制電池用量」，入口與效果依品牌、系統版本而異。這個按鈕只開啟 App 資訊頁，不會自動修改設定。已驗證的改善限該 OPPO 裝置與短期觀察，不能保證所有 OEM 或數小時不中斷。

## 怎麼選點與規劃路線？會自己隨機走嗎？

地圖預設以台北為中心；目前沒有移到手機真實位置的按鈕。可以點按地圖，或用「座標」輸入「緯度, 經度」。緯度範圍為 −90 至 90，經度為 −180 至 180。

定點使用最後選取的途經點。步行規劃接受 2–8 個有順序的途經點，服務可能將它們對齊附近可步行路網。先規劃並檢查預覽，再開始行走；規劃失敗會顯示錯誤，不會偷偷改用直線。

行走沿確認的軌跡依選定速度前進，不會隨機選方向。速度可設為 0.5–30 km/h，預設 5 km/h，行走中可以調整。這不是 Google Maps 路線，也不支援 Google Maps 分享連結或 GPX 匯入。

## 定點、暫停、停止行走與恢復真實定位有何差別？

| 操作或狀態 | 位置輸出與後續行為 |
| --- | --- |
| 定點 | 在選定位置持續輸出零速度與新的時間戳。 |
| 暫停 | 停在目前位置並保留進度，可按「繼續」從原進度行走。 |
| 停止行走 | 固定最後採樣位置，持續輸出零速度與新的時間戳；不能按「繼續」重啟這次移動。 |
| 到達終點 | 留在終點定點，不會自行返回起點。 |
| 恢復真實定位 | 結束模擬輸出並清理本 App 啟用的定位狀態；接收 App 可能跳回手機真實位置。 |

主畫面與通知提供停止行走及恢復真實定位。停止行走仍是活動中的模擬行程，編輯路線或開始另一段行程前，需先恢復真實定位。

## 可以自動往返或循環嗎？能保證位置不跳回去嗎？

目前只有單趟行走，沒有自動返回起點或循環模式。到達、暫停與停止行走都維持模擬定點。

「停止行走」不會主動釋放模擬定位，但無法保證接收 App、系統或程序中斷時的顯示行為。明確按下「恢復真實定位」會釋放輸出，接收端可能跳回真實位置；此操作不承諾平滑走回或避免跳點。

## 一定要連網嗎？資料會保存嗎？

規劃新路線需要連網，尚未快取的地圖圖磚也需要連線。已下載並保存的路線軌跡可以離線行走；沒有圖磚時仍可輸入座標定點。公共圖磚與路由服務沒有本專案專屬的可用性保證。

App 在手機本機保存最近一份草稿，包括途經點、已規劃軌跡與速度。修改途經點會使原軌跡失效，需要重新規劃。沒有多筆路線歷史；資料不參與雲端備份或裝置轉移。

重新開啟、程序重建或手機重開機都不會自動開始／續走。若原服務仍在執行，回到畫面可查看現有行程；若程序已中斷，保存的草稿不會恢復中斷時的進度。

## Pikmin Bloom 或 Pokémon GO 可以使用嗎？

在一台 OPPO Android 11 手機調整背景限制後，使用者已目視確認 Pikmin Bloom 152.0 的地圖位置持續前進。這只證明該裝置與遊戲版本的地圖移動，沒有驗證步數增加、完整遊玩、其他品牌或數小時穩定性。Pokémon GO 尚未實測。

獨立接收器收到位置，不等於遊戲接受或能正常遊玩。Route Mock 保留 Android 的模擬定位標記；接收 App 可以辨識並拒絕。本專案不提供 root 整合、隱藏模擬標記、修改遊戲或繞過偵測的功能。

## 座標會傳到哪裡？需要帳號或 API key 嗎？

不需要帳號或自行申請 API key。地圖使用 OpenStreetMap 圖磚，Leaflet 程式與樣式隨 App 打包。按下規劃時，選取座標會送到 FOSSGIS 的 `routing.openstreetmap.de/routed-foot` 服務；該服務會記錄請求。圖磚請求也會送到圖磚供應方。

App 自有程式沒有分析追蹤、背景蒐集真實位置或上傳真實位置的路徑。這不代表第三方 SDK 與系統服務已完成全面隱私稽核。供應方政策與授權請見[第三方聲明](../THIRD_PARTY_NOTICES.md)。

## 沒有 Google Play services 可以使用嗎？

Google Play services 正常時，App 同時提供 GPS、network 與 Google fused 模擬輸出。完全未安裝 Google Play services 時才使用平台定位模式；已安裝但停用、過舊或異常時會明確報錯。完整的 GMS 缺席與異常裝置矩陣尚未驗證。

## 恢復真實定位後仍顯示舊位置，或清理失敗怎麼辦？

接收 App 可能快取最後位置，恢復後需等待裝置取得新的真實定位；室內也可能暫時沒有新的 GPS 樣本。清理成功不代表接收端立即更新畫面。

強制停止或程序異常中斷可能留下待清理狀態。重新開啟 Route Mock，使用「清理並恢復真實定位」。若已將其他 App 指定為模擬位置 App，請先重新選回 Route Mock，再重試清理。

畫面若仍顯示清理中或錯誤，代表尚未確認釋放完成，不能當作已恢復真實定位。外部定位服務尚未完成的操作也可能延後清理；保留錯誤訊息以便排查，不要把「停止行走」當成清理操作。

## Release APK 可以直接覆蓋安裝嗎？

本專案的 Release 使用固定且公開的測試簽署金鑰，同一身分的較新版本可用於更新。既有 debug APK 通常使用不同簽章，需要先解除安裝；解除安裝會移除本機草稿。

任何人都能取得此公開金鑰並簽署 APK，因此相同憑證不能證明發布者身分。請從本儲存庫的 Releases 頁取得 APK；金鑰與更新限制見[簽署說明](../signing/README.md)，建置與發布指令見 [README](../README.md)。
